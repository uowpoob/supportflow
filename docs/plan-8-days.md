核对日期：2026-09-17。以当前工作区代码和本轮检查结果为准，包括尚未提交的文件。
这 8 天从现在开始，已完成的基础不重复施工。按每天约 6～8 小时、聚焦第一版可演示闭环安排，属于紧凑目标，不是工期保证；若每天仅 2～3 小时，需要延长。

## 本轮发现与紧接着的执行顺序

1. **先恢复 MySQL 连接。** 本轮只读 `SELECT 1` 在认证阶段失败：`'cryptography' package is required for sha256_password or caching_sha2_password auth methods`。当前环境缺少该依赖；先补入项目依赖与锁文件并同步环境，再检查连接、Alembic 当前版本和实际订单数据。本轮未执行种子或写入业务数据。
2. **补第 1、2 天的验收。** 增加 `/me`、退出后旧 Cookie 重放、客户/管理员 403、两个客户数据隔离、非本人和不存在统一 404、分页校验测试。随后浏览器验证登录→刷新→列表→详情→退出。
3. **核对演示数据时间。** 订单种子只在首次创建时按当前 UTC 计算日期，重跑会跳过已有订单，因此旧订单仍会自然超期。测试使用固定时钟和独立数据，不能依赖重跑种子刷新日期；演示库的数据更新另作显式操作。
4. **接退款资格，再接申请。** 先实现共享业务层的只读资格判定及规则测试，再实现申请与进度查询，最后接 Vue 申请表单。金额固定取订单实付，原因保留原文，同订单有效申请由数据库约束防重。

工作区注意：`web-vue/`、多个 API 包入口和退款/会话模块尚未跟踪；`src/supportflow/api/user.py` 是暂存新增、工作区已删除的空文件。本轮保留原有暂存状态。后续提交前应核对必要文件，避免只提交引用方而漏掉新模块。

启动配置注意：Vue 位于 `127.0.0.1:5174`，代理后端到 `127.0.0.1:8080`；后端与此前 README 的 8000 端口需要对应。当前主用前端尚未由本轮确认，后续计划暂以新增 Vue 实现为接线依据。

检查边界：本轮未进行真实数据库业务验收、浏览器操作或模型调用；PostgreSQL、Milvus 状态未复核。pytest 有依赖弃用和缓存目录写权限警告，测试本身通过。

## 执行原则

- 每天把相关前端和测试一起做，不再单独花一天制作随后被真实 API 替换的模拟页面。
- 第 4 天是业务验收点：如果权限、事务、并发防重还不可靠，先修复，再接 Agent。
- 第 5 天同时处理会话归属和持久化，避免先做临时记忆再返工。
- 第 6 天用少量文档和固定问题完成完整检索路线；评测样本随各模块积累，最后一天汇总。
- 每天验收后再进入下一步。时间不够先减少界面装饰、文档规模和调参轮数，不删除权限、幂等和数据隔离。
- 区分“代码已实现”“自动检查通过”“真实环境验收通过”；数据库不可用时不把模拟测试结果记为业务验收完成。
