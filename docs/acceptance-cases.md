本文件是待实现的规范，不是已通过测试或实测成绩。每个 ID 后续对应独立案例；语言类案例要加入人工审核的表达变体，不能只匹配关键词。

## 固定数据与断言

时钟：2026-09-14T00:00:00Z，每例重置数据。U1拥有A1001（签收10天，实付29900分）、A1002（15天）、A1003（未支付）、A1004（已退款）、A1005（另一正常订单）；U2拥有B1001；管理员M1。默认已支付已签收，边界场景覆盖时间字段。政策demo-refund-v1为14天全额退款。
这些数据尚未落库。检索阶段另建旧版、不同商品、重复、冲突及恶意片段，标注适用条件。
业务结果以MySQL状态、金额、记录数断言；恢复检查PostgreSQL状态并核对MySQL；引用检查文档、条款与版本。

## 量化方式与执行顺序

共67个场景。每例记录case_id、场景族、身份、历史、初始数据、输入、预期意图/工具/参数/状态/引用、禁止动作、数据集版本。
A类单意图样本统计Accuracy和Macro-F1；多任务样本另统计子任务覆盖率，不强塞进单标签准确率。
B/D/E类用确定性断言验证权限、事务、金额和记录数；注入并发与故障，LLM裁判不能替代数据库检查。
C类人工标注相关片段与证据，报告逐问题Recall@5、回答级幻觉率及覆盖率；LangSmith管理实验和复核。
F类记录P50/P95、Token、费用、重试次数、失败阶段；基线后设置性能预算。
本矩阵是开发规范，独立测试数据还需另行编写与人工审核，按场景族隔离；每次报告样本数、分子、分母和失败案例。
先落地B类基础规则与D类业务权限；接入Agent后实现A类；再C类检索、E类恢复及F类运行评测。避免第一次开发同时展开全部模块。
